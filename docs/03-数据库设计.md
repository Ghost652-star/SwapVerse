# 数据库设计

| 项目 | 内容 |
|---|---|
| 项目名称 | 易易物（校园物品交换小程序） |
| 数据库 | MySQL 8.0 |
| 编写 | 陈俊宇 |
| 复核 | 周晓明 |
| 日期 | 2026年10月 |

## 1. 数据表清单

| 表名 | 存放内容 |
|---|---|
| user | 用户信息 |
| category | 物品分类 |
| goods | 物品信息 |
| goods_image | 物品图片 |
| message | 留言 |
| favorite | 收藏记录 |
| exchange | 交换申请与交换单 |

建表脚本为 `server/db/schema.sql`，演示数据为 `server/db/seed.sql`。

## 2. 设计说明

1. 字符集统一采用 utf8mb4。物品标题、描述与留言中可能出现表情符号，使用 utf8 会出现存储失败；
2. 不建立物理外键。数据一致性由服务端业务逻辑保证，避免删除数据时受外键约束影响；
3. 图片单独建表。一件物品最多 9 张图片，单独存放便于排序，列表页只读取排序最靠前的一张作为封面；
4. 交换申请与交换单合并为一张表，以状态字段区分。接受申请时只需修改状态并锁定物品，不必在两表之间迁移数据，可避免数据不一致；
5. 状态以数字存储。占用空间较小且便于建立索引，具体含义在代码中以常量表示。

## 3. 表结构

### 3.1 user（用户）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键，自增 |
| openid | varchar(64) | 微信用户标识，唯一 |
| nickname | varchar(64) | 昵称，默认“微信用户” |
| avatar | varchar(255) | 头像地址 |
| contact | varchar(128) | 联系方式，交换达成后对双方可见 |
| campus | varchar(64) | 校区或宿舍楼 |
| credit_done | int | 已完成交换次数 |
| credit_report | int | 被投诉次数 |
| role | tinyint | 0 普通用户，1 管理员 |
| status | tinyint | 0 正常，1 禁用 |
| created_at | datetime | 注册时间 |

### 3.2 category（分类）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 主键 |
| name | varchar(32) | 分类名称 |
| sort | int | 排序值，数值越小越靠前 |

初始化数据为 8 个分类：教材书籍、数码电子、生活用品、运动器材、衣物服饰、美妆护肤、零食饮品、其他。

### 3.3 goods（物品）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| user_id | bigint | 发布人 |
| category_id | int | 所属分类 |
| title | varchar(64) | 标题 |
| condition | varchar(16) | 成色 |
| expect | varchar(128) | 期望换得的物品 |
| description | text | 详细描述 |
| status | tinyint | 0 待审核，1 已上架，2 交换中，3 已换出，4 已下架，5 已驳回 |
| reject_reason | varchar(255) | 驳回理由 |
| created_at | datetime | 发布时间 |
| updated_at | datetime | 修改时间 |

建立三个索引：user_id 用于查询本人发布的物品；status 与 category_id 联合索引用于首页按分类查询已上架物品；created_at 用于按时间倒序分页。

### 3.4 goods_image（物品图片）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| goods_id | bigint | 所属物品 |
| url | varchar(255) | 图片地址，保存相对路径 |
| sort | int | 排序值，0 为封面 |

图片仅保存相对路径，后续若迁移至对象存储，无需修改数据库。

### 3.5 message（留言）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| goods_id | bigint | 所属物品 |
| user_id | bigint | 留言人 |
| parent_id | bigint | 被回复留言的编号，可为空 |
| content | varchar(500) | 留言内容 |
| created_at | datetime | 留言时间 |

回复仅支持一层，即回复的回复统一归入同一条留言之下，满足使用需要且实现较为简单。

### 3.6 favorite（收藏）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| user_id | bigint | 用户 |
| goods_id | bigint | 物品 |
| created_at | datetime | 收藏时间 |

对 user_id 与 goods_id 建立唯一联合索引，同一用户对同一物品仅保留一条记录，重复收藏不会产生多余数据。

### 3.7 exchange（交换申请与交换单）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| applicant_id | bigint | 申请方 |
| target_goods_id | bigint | 被申请的物品 |
| offered_goods_id | bigint | 申请方用于交换的物品 |
| message | varchar(255) | 申请留言 |
| status | tinyint | 0 待处理，1 进行中，2 已拒绝，3 已取消，4 已完成 |
| applicant_confirmed | tinyint(1) | 申请方是否已确认 |
| owner_confirmed | tinyint(1) | 物品所有者是否已确认 |
| created_at | datetime | 申请时间 |
| finished_at | datetime | 完成时间，未完成时为空 |

表中未单独保存物品所有者编号，可通过 target_goods_id 查询物品得到，避免冗余字段与物品信息不一致。

## 4. 演示数据

导入 seed.sql 后包含：8 个分类；3 个账号，分别为 admin_mock（管理员）、user_a 与 user_b；6 件已上架物品，分布于教材书籍与数码电子两类。

服务端启用模拟登录模式时，登录请求中的 code 填写 user_a 即可以该账号身份登录，无需真实微信环境。

## 5. 建库步骤

```bash
mysql -u root -p --default-character-set=utf8mb4 < server/db/schema.sql
mysql -u root -p --default-character-set=utf8mb4 < server/db/seed.sql
```

两条命令均须携带字符集参数，否则建表时含中文默认值的语句会报 ERROR 1067。

执行完成后可按下述语句核对：

```sql
USE yiyiwu;
SHOW TABLES;                 -- 应返回 7 张表
SELECT COUNT(*) FROM goods;  -- 应为 6
SELECT name FROM category;   -- 应显示 8 个中文分类
```
