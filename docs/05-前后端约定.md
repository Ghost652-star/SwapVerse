# 前后端约定

| 项目 | 内容 |
|---|---|
| 项目名称 | 易易物（校园物品交换小程序） |
| 编写 | 陈俊宇 |
| 日期 | 2026年10月 |

## 1. 编写目的

项目由三人并行开发，若返回格式、字段命名与错误提示未事先统一，联调阶段需反复修改。本文档针对最容易出现分歧的方面作出约定，作为前后端共同遵循的规则。

## 2. 统一返回格式

```json
{ "code": 0, "message": "ok", "data": { } }
```

失败时：

```json
{ "code": 1001, "message": "对方物品当前不可交换", "data": null }
```

前端处理方式固定为三条：code 为 0 时取 data 使用；code 非 0 时直接显示 message；接收 401 时清除本地登录信息并跳转登录页。前端不根据 code 自行组织提示语。

## 3. 字段命名

| 位置 | 规则 | 示例 |
|---|---|---|
| 数据库 | 下划线 | reject_reason、created_at |
| 接口与代码 | 驼峰 | rejectReason、createdAt |

命名转换在服务端数据访问层完成，接口返回时已为驼峰形式，前端无需了解数据库字段名。

## 4. 数据类型

| 类型 | 约定 |
|---|---|
| id | 直接返回数据库查询结果，bigint 编号返回为字符串 |
| 时间 | 字符串，格式为 `2026-11-05 14:22:01` |
| 布尔值 | true 或 false，不使用 0 与 1 |
| 金额 | 本项目不涉及 |

## 5. 列表与分页

请求参数为 pageNum（从 1 开始）与 pageSize（默认 20）。返回结构为：

```json
{ "code": 0, "message": "ok",
  "data": { "total": 6, "pageNum": 1, "pageSize": 20, "list": [] } }
```

前端判断是否还有下一页时，比较 pageNum 与 pageSize 的乘积是否小于 total。

## 6. 图片

1. 上传接口为 POST /api/upload，表单字段名为 file，每次上传一张；
2. 成功返回 `{ "url": "/uploads/20261105/a.jpg" }`；
3. 数据库与接口均保存相对路径，显示时由前端拼接服务器地址；
4. 限制条件：单张不超过 5MB，仅允许 jpg、png、webp 格式，单次发布最多 9 张。

## 7. 错误提示

message 内容直接面向使用者，不使用 parameter invalid 一类的表述。已统一的主要提示如下：

| 情形 | 提示内容 |
|---|---|
| 未填写标题 | 参数校验失败：title 不能为空 |
| 申请本人发布的物品 | 物品状态不允许当前操作：不能申请交换自己发布的物品 |
| 物品已被锁定 | 对方物品当前不可交换 |
| 重复接受申请 | 交换单状态不允许当前操作：仅待处理的申请可接受 |
| 驳回未填写理由 | 参数校验失败：reason 不能为空 |
| 账号已禁用 | 用户被禁用 |

## 8. 登录与权限

1. 登录成功后返回 token，小程序保存于本地，后续请求置于请求头 `Authorization: Bearer xxx`；
2. token 有效期为 7 天，失效时返回 401；
3. 需登录的接口未携带 token 时直接返回 401，不返回空数据；
4. 管理接口另行判断角色，角色不为管理员时返回 403 与 1002。

## 9. 需要共同注意的事项

1. 状态值不在页面中直接写为数字，前端统一从状态对照文件读取文字与颜色，服务端统一使用常量；
2. 交换的接受、取消与确认涉及多表写入，必须在同一事务内完成，前端在这几个接口上点击后应禁用按钮，避免重复提交；
3. 删除物品时须同时删除图片记录与留言，由服务端在删除接口内处理，前端仅调用删除接口。

## 10. 联调问题定位顺序

1. 先使用命令行或接口调试工具直接调用接口，确认返回内容是否正确；
2. 返回正确而页面显示异常，属于前端问题；
3. 返回异常，查看服务端日志与数据库中的数据；
4. 中文出现乱码时，先确认请求是否以 GBK 编码发出（Windows 命令行常见），再排查代码。
